# 전국 상수관망 벡터타일 변환

전국 상수관망 gpkg를 지도용 벡터타일(MVT)로 바꾸는 스크립트입니다. 시연 화면이 쓰는 `tiles_national/kict_national` 타일을 이 스크립트로 만들었습니다.

## 구성

| 파일 | 역할 |
|---|---|
| `tools/convert_national.py` | 변환 스크립트 |
| `README_타일변환.md` | 이 문서 |

## 입력

| 레이어 이름 | 파일 | 원본 건수 | 남기는 속성 |
|---|---|---|---|
| `kict_national` (건기연 상수관망) | `건기연상수관망.gpkg` (약 2.5GB) | 4,440,047 | FTR_IDN, STD_DIP, MOP_CDE |

- gpkg 안의 레이어 `_`(기하 열 `geom`)를 읽습니다. 구역을 나눌 때 gpkg의 공간 색인 표 `rtree___geom`을 씁니다.
- 원본 좌표계 EPSG:32652를 EPSG:3857로 바꿔 타일을 만듭니다.
- 기하는 선(MultiLineString)이며 단순화(SIMPLIFICATION)는 하지 않습니다.

## 도구

- Python 3.13
- pyogrio 0.13.0 (GDAL 3.12.4 포함, GDAL의 MVT 드라이버 사용), shapely 2.2.0, pyproj 3.8.0, numpy 2.5.4
- 별도 GDAL·tippecanoe 설치는 필요 없습니다.

```
python -m venv .venv
.venv\Scripts\python -m pip install pyogrio==0.13.0 shapely==2.2.0 pyproj==3.8.0 numpy==2.5.4
```

## 폴더 구조와 실행 위치

저장소에서는 스크립트가 `tools/`에 있으므로 **경로 옵션 3개를 모두 줍니다.** 저장소 맨 위에서 실행하고, gpkg는 `건기연상수관망/`에 둡니다. gpkg는 저장소에 없습니다.

```
저장소/
├─ 건기연상수관망/                  ← gpkg를 여기에 둠
│   └─ 건기연상수관망.gpkg
├─ tools/convert_national.py
└─ backend/data/
    ├─ tiles_national/kict_national/  ← 결과
    └─ tiles_national_work/           ← 작업용 임시 폴더
```

## 실행 예시

```
# 저장소 맨 위에서
# 1단계: z6~z12
python tools/convert_national.py 6,7,8,9,10,11,12 all --src 건기연상수관망/건기연상수관망.gpkg --out-dir backend/data/tiles_national/kict_national --work-dir backend/data/tiles_national_work

# 2단계: z13~z17
python tools/convert_national.py 13,14,15,16,17 all --src 건기연상수관망/건기연상수관망.gpkg --out-dir backend/data/tiles_national/kict_national --work-dir backend/data/tiles_national_work

# 일부 구역만 시험 (z8 구역 번호 x/y)
python tools/convert_national.py 10 218/99 --src 건기연상수관망/건기연상수관망.gpkg --out-dir backend/data/tiles_national_test --work-dir backend/data/tiles_national_work

# 도움말
python tools/convert_national.py --help
```

- 저장소에 이미 타일이 있으므로 다시 만들려면 다른 `--out-dir`을 쓰세요.
- 인자: `줌목록 [구역]`. 구역을 생략하거나 `all`이면 전국 전체입니다.
- z6·z7은 결과 폴더에 그 줌 폴더가 이미 있으면 건너뜁니다.
- z8 이상은 구역마다 작업 폴더에 완료 표시(`done_…`)를 남기고, 다시 실행하면 완료된 구역을 건너뜁니다. 같은 줌을 처음부터 다시 만들려면 작업 폴더의 완료 표시를 지우거나 새 작업 폴더를 씁니다.
- 한 번에 한 프로세스로 줌별·구역별로 차례대로 변환합니다. 작성 PC에서 최대 메모리는 약 4GB였습니다.

## 줌 구간

| 줌 | 구간 | 처리 |
|---|---|---|
| 6~10 | 간략화 | GDAL MVT 기본 동작(격자에서 한 점으로 뭉개지는 짧은 선은 빠짐) + 타일 1장 압축 후 5MB 상한(`MAX_SIZE` 5,000,000) |
| 11~17 | 원본 전량 | 원본 선을 모두 넣음. 짧은 선은 아래 '짧은 선 처리'대로 남김. 타일 크기·건수 상한 사실상 없음 |

- z6·z7은 전국을 한 번에 변환합니다. 메모리를 아끼려고 그 줌 격자 0.7칸 이상인 선만 읽습니다(그보다 짧은 선은 어차피 빠짐).
- z8 이상은 z8 타일 한 칸을 한 구역으로 하여 19개 구역을 차례대로 변환합니다. 구역 범위와 겹치는 선을 읽어 변환하고, 그 구역에 속한 타일만 결과 폴더로 옮깁니다. 구역 경계를 넘는 선은 이웃 구역에서도 읽히므로 양쪽 타일에 모두 들어갑니다.

## 짧은 선 처리 (z11~z17)

- 줌마다 격자 1칸 크기가 정해집니다. 격자 2칸보다 짧은 선은 그대로 두면 한 점으로 뭉개져 타일에서 빠집니다.
- 이런 선은 같은 위치(중심)와 같은 방향으로 길이 3칸인 선으로 바꿔 남깁니다. 그래서 원본 선이 모두 타일에 들어갑니다.
- 바뀐 선은 화면에서 1픽셀 미만입니다.
- 바뀐 선은 원래 길이가 아니므로 **길이 계산에는 쓰지 마세요.**
- 그 밖의 선은 원본 모양 그대로입니다.

## 검증 결과

- z11~z17: 원본 4,440,047행마다 선 위 대표점이 속한 타일에 같은 FTR_IDN을 가진 선이 격자 3칸 안에 있는지 확인했습니다. z11~z16은 모든 행이 통과했습니다.
- z17은 2행이 3칸을 조금 넘었습니다. 길이 약 5.2km인 긴 선을 3857 좌표로 그릴 때 생기는 0.28m 차이 때문이며, 두 행 모두 타일에 들어 있습니다.
- FTR_IDN은 전국에서 고유하지 않습니다(고유값 3,481,700개). 고유 FTR_IDN 기준으로는 z11~z17 모두 100% 포함입니다.
- z6~z10은 간략화 구간이라 원본 전량이 아닙니다(고유 FTR_IDN 포함 비율 z6 9.83% ~ z10 54.78%).

## 만들지 않은 줌

- z0~z5는 만들지 않았습니다. 시연 화면은 전국 전체 화면보다 축소되지 않으며, 1920×1080 화면에서 전국 전체 화면(100%)은 z6 타일을 씁니다.
