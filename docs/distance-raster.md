# 거리 래스터 화면 실행 안내

## 접속과 조작

서버 실행 후 **`/app/`**에 접속합니다. `frontend/index.html`이 레이어 지도를 직접 제공하며 별도 페이지 이동이 필요하지 않습니다. 이전 `/app/distance.html` 주소도 동일한 메인 화면을 제공합니다. 기존 전국 시나리오 측정은 속도 측정 카드의 링크로 엽니다.

화면 배치는 **왼쪽 레이어 선택 / 오른쪽 위 속도 측정 / 오른쪽 아래 범례**입니다. 격자 조회 결과는 지도 클릭 시 별도 카드로 나타나며 닫을 수 있습니다. 작은 화면에서는 왼쪽 목록을 `레이어` 버튼으로 엽니다. 범례 색상 설정은 오른쪽 아래 버튼에서 열고, 측정 반복 설정은 오른쪽 위 `반복 측정·측정 기준`에 있습니다.

배경지도와 벡터 목록은 거리 파일 조회보다 먼저 초기화합니다. 거리 API 오류나 파일 누락이 있어도 지도 이동·벡터 선택을 사용할 수 있고, 다른 TIF 자료 선택 또는 같은 항목 재선택으로 다시 조회할 수 있습니다. `/health`는 정상인데 `/distance/meta`가 404이면 실행 중인 백엔드에 새 경로가 반영됐는지 확인합니다. `git pull` 후에도 기존 Python 프로세스는 자동 갱신되지 않으므로 서버 서비스를 재시작해야 합니다.

왼쪽 벡터타일 목록은 기존 `APP_CONFIG.LAYERS`를 사용합니다. `/tiles/{id}/meta.json`에서 자료가 확인되면 선택할 수 있고 TIF 위에 함께 표시합니다. 데이터가 없으면 해당 항목을 `자료 없음`으로 표시합니다. TIF는 **건기연 상수(서울)**와 **건기연 하수(서울·보정본)** 각각 Case 1·2, 총 네 항목 중 하나씩 선택하며, 모두 끄고 벡터만 볼 수도 있습니다.

하수 자료를 처음부터 선택하려면 `/app/?dataset=kict_sewer_seoul`로 접속합니다. 자료를 바꾸면 래스터·격자선·클릭 조회·result 다운로드가 함께 바뀝니다. 속도 기록과 CSV에는 자료 구분이 포함되며, 상수와 하수의 평균은 따로 계산합니다. `두 방식 반복`은 현재 선택한 자료의 Case 1·2를 반복합니다.

TIF를 켠 상태에서 줌 13 이상으로 확대하면 실제 유효 셀의 **100m 격자 경계**가 0.6px 선으로 표시됩니다. 공유 경계는 한 번만 그리며 NoData 내부에는 격자선을 만들지 않습니다. 전체 보기에서는 숨기고, TIF 선택·해제 및 불투명도와 함께 바뀝니다. 원본 TIFF는 수정하지 않으며 격자선은 별도 오버레이입니다.

래스터 재투영에는 화면 최대 줌 20까지의 출력 격자를 명시합니다. 기본 설정은 원본 100m 해상도 부근에서 재투영 확대 단계를 제한해, 확대 시 거친 화면 픽셀을 늘리면서 원래 격자선과 색상 경계가 어긋났습니다. 현재는 화면 확대 수준으로 다시 재투영하며 원본 값을 최근접 방식으로 표시합니다. 원본 TIFF의 값·좌표는 변경하지 않습니다. 렌더링 작업량이 달라졌으므로 수정 전 속도 기록과는 구분해 측정합니다.

오른쪽 측정 카드의 `벡터타일` 탭은 켜진 벡터의 현재 화면 표시 시간을 별도로 기록합니다. TIF와 벡터는 같은 위치·배율을 공유하는 별도 렌더러를 쓰므로 서로의 네트워크 로딩 완료를 기다리지 않습니다. CPU/GPU 부하의 영향은 공유합니다. 기존 전국 시나리오 측정은 해당 탭의 링크로 유지합니다.

1. **Case 1**: 격자 중심에서 최근접 관로까지의 거리. **Case 2**: 관로가 통과한 격자는 0, 나머지는 Case 1 거리.
2. 색이 있는 격자를 클릭하면 원래 `grid_id`로 result를 조회합니다. 두 거리값, 관로 통과 여부, `pipe_id`, 최근접점 좌표가 나옵니다. 파랑 점은 격자 중심, 빨강 점은 최근접점, 점선은 두 점 사이의 조회선입니다.
3. **원본 다시 읽고 측정**으로 현재 Case를 다시 측정합니다. **두 방식 반복**은 각 Case를 지정 횟수만큼 번갈아 측정합니다. 중단·기록 보기·CSV 저장을 지원합니다.
4. 확대·이동하면 재표시 시간을 별도로 기록합니다. **색상·거리 구간 설정**에서 임계값과 색상을 바꿉니다. 이 설정은 해당 브라우저에만 저장됩니다.

## 배포

저장소 루트에서 최신 변경을 받은 뒤 **기존 서버가 사용하는 Python 가상환경**으로 실행합니다.

Python 3.9에서는 Pillow 11.3.0이 자동 선택됩니다. [Pillow 12의 Python 3.9 지원 종료](https://pillow.readthedocs.io/en/stable/releasenotes/12.0.0.html#python-3-9) 때문에 설치 조건을 분리했으며, Python 3.10 이상에서는 기존 Pillow 12.0.0을 사용합니다.

```sh
git pull
python -m pip install -r backend/requirements-server.txt
```

실행 중인 서버는 기존 운영 방식으로 재시작합니다. `git pull`만으로 이미 실행 중인 Python에 새 API가 반영되지는 않습니다. 신규 설치라면 루트 README의 서버 실행 절차를 따릅니다. 별도 Node 빌드나 DB 연결은 필요 없습니다.

새 데이터는 Git에 포함하지 않습니다. `backend/data/`는 ignore 대상으로, 아래 각 자료 폴더의 네 파일을 서버에 직접 업로드합니다. 이미 추적 중인 기존 데이터에는 ignore가 소급 적용되지 않습니다.

상수 API는 기존 `/distance/`, 하수 API는 `/distance/kict_sewer_seoul/`입니다. 하수 입력 관망은 `public.swl_pipe_lm_11_roadtypes_final_20261117`이며, result의 `pipe_id`는 이 최종 관망의 `id`입니다. `ORG_IDN`과 구분합니다.

네 TIF는 EPSG:32652, 370×303셀, 100m 격자, NoData=-9999입니다. 브라우저가 원본 파일을 통째로 읽고 웹 지도에 재투영합니다. 타일 분할이나 원본 재가공은 적용하지 않았습니다. OpenLayers·GeoTIFF.js 번들과 라이선스는 `frontend/vendor/`에 포함했습니다.

배경은 기존 `frontend/config.js`의 네이버 키를 사용합니다. 키가 없거나 연결에 실패하면 OpenStreetMap으로 표시하고 화면에 알립니다. 외부 배경지도에는 인터넷 연결이 필요합니다.

로컬 실행에서는 기존 공개 Client ID를 `NAVER_CLIENT_ID` 환경변수로 전달하고 `http://localhost:8012/app/distance.html`로 접속합니다. 확인한 네이버 등록 설정은 `localhost`에서 인증되며 `127.0.0.1`에서는 인증 오류가 발생했습니다. Client ID 값을 저장소에 추가하지 않습니다. 네이버 스크립트 로딩 후 인증이 실패하는 경우에도 대체 배경과 안내 문구로 전환합니다.

네이버 API는 배경 컨테이너에 `position:relative`를 직접 설정합니다. `inset:0`만으로 크기를 잡으면 높이가 0이 되어 타일을 정상 수신해도 배경이 보이지 않습니다. `#base`에 너비·높이 100%를 명시해 지도 영역을 채우도록 했습니다. 실제 인앱 화면에서 수정 전 높이 0px, 수정 후 지도 영역과 같은 957px을 확인했고 도로·지명이 래스터 아래 표시되는 것을 확인했습니다. 배경 검증은 인증/이미지 수신과 함께 컨테이너의 실제 크기도 확인합니다.

배경의 중심·배율은 OpenLayers의 `precompose`에서 **지금 그릴 프레임의 카메라**를 사용해 네이버 `updateBy`로 함께 갱신합니다. `change:center`/`change:resolution`에서 먼저 배경만 움직이는 방식은 제거했습니다. 휠·트랙패드는 정수 줌 단계로 즉시 변경하고 더블클릭·키보드 확대 애니메이션도 0ms로 설정했습니다. 네이버가 정수 줌을 사용하는 동안 격자만 중간 배율로 커지는 현상을 방지합니다.

## result 연결 방식

엑셀에는 격자 중심 좌표가 없으므로, 원본 격자 `GRID.[Grid]b_격자모양_SGIS내륙정보`의 **동일한 ID에 해당하는 실제 도형 중심 좌표**로 대응표를 만들었습니다. 엑셀 행 순서·ID 순서·거리값의 유사성으로 위치를 추측하지 않았습니다.

지도 클릭 → EPSG:32652 변환 → TIF 행·열 계산 → 선택한 자료의 `grid_index.json`에서 `grid_id` 확인 → 해당 result의 같은 `grid_id` 조회 순서입니다. 상수는 XLSX, 하수는 CSV를 읽습니다. NoData와 유효한 0값은 분리합니다. `pipe_id`는 문자열로 전달합니다.

서버는 최초 조회 또는 입력 파일 변경 시 다음을 확인하고, 읽은 result를 메모리에 보관합니다.

- TIF 2개와 대응표의 좌표계·크기·원점·셀 크기·NoData 일치
- 격자 위치 및 ID 중복 없음, 대응표와 result의 ID 집합 일치
- 60,579개 격자의 두 거리값이 TIF와 result에서 일치: float32 저장 오차를 고려한 절대 0.001m 또는 상대 0.0002% 허용
- TIF 유효 셀 수와 result 행 수 일치

입력 셋이 다르면 조회를 중단하고 오류를 알립니다. 앞으로 격자 범위나 ID가 달라진 자료로 교체할 때는 **그 자료의 원본 격자로 대응표도 다시 생성**해야 합니다.

## 속도 수치의 의미

| 화면 수치 | 측정 범위 |
|---|---|
| 다운로드 | 원본 TIF 요청 시작부터 전체 바이트 수신까지 |
| 해석·표시 | 수신 완료부터 GeoTIFF 해석·재투영·그리기 완료 후 두 프레임 대기까지 |
| 다운로드부터 표시까지 | 위 두 시간의 합계 |
| 확대·이동 재표시 | 마지막 위치·배율 변경부터 재표시 완료 후 두 프레임 대기까지. 원본 재전송 없음 |

`rendercomplete`와 브라우저 프레임 대기로 측정한 **화면 준비 시간**이며 GPU만의 실행 시간은 아닙니다. 배경지도·result 조회·별도 격자선의 완료를 기다리는 시간은 TIF 측정에서 제외합니다. 동시에 실행되는 배경 작업에 따른 CPU/GPU 부하는 영향을 줄 수 있습니다.

원본 요청은 HTTP 캐시를 우회하고 GeoTIFF 소스도 새로 만듭니다. 서버 OS 파일 캐시나 연결까지 초기화하지는 않습니다. 기록의 파일 용량은 원본 바이트 수이며 실제 네트워크 압축 전송량과 다를 수 있습니다. 동일한 화면 크기·위치·배율에서 비교하세요.

오류·중단은 성공 평균에서 제외합니다. 측정 중 탭을 숨기거나 새 이동을 시작한 경우 이전 재표시 측정도 폐기합니다. CSV에는 실패 기록도 상태와 함께 남습니다. 최초 result 검증·로딩은 원본 TIF 측정 시작 전에 수행합니다.

- 통합 레이아웃 변경 후 실제 TIF 선택·해제·범례·격자 팝업·기존 측정 기능과 1440×900 / 1280×720 / 390×844 화면 확인.
- 최초에는 실행 폴더에 벡터 데이터 경로가 없어 MVT 테스트 응답으로 오류·취소를 검증했음. 후속 확인에서 기존 `임시/수열관로테스트서버/water-pipe-speed-main/water-pipe-speed-main/backend/data/tiles_national` 원본을 찾았고, 현재 프로젝트의 `backend/data/tiles_national`에 로컬 디렉터리 연결을 생성함. 실제 타일 HTTP 200 응답 21건, MVT 형상 파싱, TIF 중첩 및 서울 시내 확대 표시를 브라우저에서 확인했음. 기존 파일을 복사하거나 변경하지 않았으며 이 로컬 경로 연결은 Git에 포함되지 않음. 배포 서버는 기존 서버의 타일 경로를 사용함.
- 이전 위치의 지연된 타일 오류가 현재 화면 측정에 섞이지 않도록 현재 줌·타일 범위를 확인하고 화면 밖 요청을 취소함. 취소된 타일은 재방문 시 다시 요청됨.
- 유효 셀 전체의 경계 일치 및 공유 경계 중복 없음 검사 포함 Flask 23건 통과. 격자 표시·축소 시 숨김·TIF 연동·실제 관로 중첩·네이버 정상 인증 및 지연 인증 오류 전환 확인. 기존 거리 화면 브라우저 회귀 검사 16건 통과.
- 후속 화면 검증에서 격자 좌표만 확인하는 검사로는 래스터 재투영 오차를 잡지 못했음을 확인함. 재투영 확대 단계 수정 후 실제 원본 TIFF 두 개, 3개 위치, 줌 13/14/16/18/20에서 4,980개 표시 값을 원본과 대조해 통과함. 경계 양쪽을 포함하되 화면 픽셀 반올림 영향을 피하도록 경계에서 2픽셀 이상 떨어진 위치를 검사함. 사용자 제보 격자 `16300925` / 관로 `1113143800`의 색상 경계와 선택 사각형도 같은 위치에서 시각 확인함. 기존 거리 화면 회귀 검사 16건 재통과.
- 이동 정합 검사: 수정 전 휠 확대 최대 167.97px, 연속 이동 최대 34.07px 차이 재현. 같은 프레임으로 갱신하고 확대 애니메이션을 정리한 뒤, 실제 관로를 켠 검사에서 휠 0.71px 미만·연속 이동 0.83px 미만·확대 버튼 0.46px 미만, 래스터/벡터 화면 좌표 차이 0px 확인. `/app/tests/map-sync.html`에서 실제 네이버 이미지 타일의 화면 위치와 관망 좌표를 매 프레임 비교함. 이 수치는 검사한 브라우저·동작의 관찰값이며 모든 입력 장치에 대한 보증은 아님.

벡터 연동 API 참고: [OpenLayers VectorTile](https://openlayers.org/en/latest/apidoc/module-ol_source_VectorTile-VectorTile.html), [MVT 읽기](https://openlayers.org/en/latest/apidoc/module-ol_format_MVT-MVT.html).
