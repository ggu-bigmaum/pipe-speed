# 관로 일치 강조 캐시 개선 — 2026-11-27

## 변경 이유와 결과

Windows PBF로 사전 생성한 캐시는 Linux 경로 및 MBTiles 저장 방식에서 경로·크기·수정 시각 키가 달라 재사용되지 않았다. 웹에서 전체 형상 비교를 재실행한 것은 아니지만, 타일 속성과 저장된 대응 관계를 다시 조회하고 비트를 구성하는 비용이 발생했다.

이제 디스크 캐시 식별은 `tile-content-v1, 표시 규칙 버전, 비교 패키지 버전, 상수/하수, 레이어, z/x/y, 압축 해제 MVT SHA, 상대 타일 SHA`로 한다. 저장 경로·압축 형태·복사 시각에 의존하지 않는다. 상수/하수의 MATCH 판정 기준, 좌표, 표시 색상 및 중복 숨김 조건은 바꾸지 않았다.

## 동작

- 파일 크기·mtime·ctime·inode는 프로세스 내 32개/16MB 제한 메모리 캐시의 변경 감지 힌트다. 디스크 식별자가 아니다. 데이터 배포는 원자적 파일 교체를 권장한다.
- 메모리 캐시가 없으면 현재 MVT 내용 SHA를 확인한다. PBF는 스트림으로 읽고, gzip 해제 내용은 최대 1MiB씩 해시한다. MBTiles는 기존 서버와 동일한 XYZ 행 관례를 유지하며 SQL에서 길이를 검사한 뒤 최대 256MiB BLOB을 읽는다.
- 내용 확인은 네 자료 전체에서 동시에 최대 2건이다. 무거운 판정 재구성 세마포어와 별개라, 이미 만들어진 캐시 조회가 무거운 재계산 뒤에 줄을 서지 않는다.
- 구형 키도 표시 규칙·패키지 버전·현재 타일과 상대 타일 SHA·비트 길이/개수 검증을 통과하면 판정 재계산 없이 새 키로 자동 전환한다. 상대 증명이 없는 구형 건기연 규칙은 재사용하지 않는다.
- 타일이나 상대 타일, 패키지가 바뀌면 재계산한다. 처리 중 변경도 검사한다. 브라우저의 실제 타일 SHA와 객체 순서 검증은 유지한다.
- 성공한 일치 타일 응답은 ETag 및 `public, max-age=0, must-revalidate`. 브라우저는 `cache: no-cache`로 재검증한다. 변경 없으면 304, 변경 시 새 응답. 오류는 계속 no-store. metadata 요청은 기존 no-store 유지.
- 권위 있는 비교 SQLite는 읽기 전용이다. 별도 tile_cache.sqlite만 갱신된다. cache_metadata에 키 형식을 기록한다.
