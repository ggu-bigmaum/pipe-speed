## 디스크 캐시

실제 앱 `backend/data/comparison/water/tile_cache.sqlite` 및 `backend/data/comparison/sewer/tile_cache.sqlite`의 `tile_flags` 테이블에 저장한다.

키는 자료·줌·타일 X/Y이며, 입력 검증에는 비교 패키지 버전, 원본 타일의 경로·크기·수정 시각, 표시 규칙 버전, 상대 타일의 정보가 포함된다. 원본 또는 기준이 변경되면 해당 캐시를 다시 만든다. 동일 크기·동일 수정 시각으로 파일을 강제로 덮어쓴 경우에도 브라우저의 원본 바이트 SHA 검증이 실패하면 숨기지 않는다.

원본 비교 SQLite는 읽기 전용으로 사용한다. 캐시는 재생성 가능한 별도 SQLite이며, 동시 조회·쓰기 및 프로세스 재시작 후 재사용을 지원한다. 이동 시 수정 시각이 달라지면 해당 타일의 캐시는 재계산될 수 있다.

사전 생성 명령:

```powershell
python tools/comparison/warm_tiles.py --data backend/data --pair water --report water-cache.json
python tools/comparison/warm_tiles.py --data backend/data --pair sewer --report sewer-cache.json
```

서울시 타일이 존재하는 좌표를 기준으로 양쪽을 처리한다. 원래 건기연 타일이 없는 좌표는 `missing`으로 분리하며 새 관로를 만들어 채우지 않는다. 보고서의 `completed`는 타일·자료 조합 수다. 여러 줌/타일에 중복되는 객체 수를 고유 관로 수로 해석하면 안 된다.
